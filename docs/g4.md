# G4: unmanaged remote storage

## Failure handling and the circuit breaker

The breaker keeps two streaks of consecutive failures, counting at most one
failure per logical operation (one fetch, one deliver, one spill or one
check):

| Streak | Counts | Reset by |
| --- | --- | --- |
| Check | A check error, a started check past its deadline, a read-error probe that errors | Any answered check, a probe that finds the block gone |
| Data | A READ or WRITE error, a read past its deadline, a spill past its deadline, a spill or publish error, a probe that finds the block still there | A successful read or an in-time spill |

- Never counts: a check that answers absent or present, a check cancelled
  while still queued, a missing file or a size mismatch at open, a late
  answer to a check already counted at its deadline, a late spill DONE.
- After a read error a probe (a re-stat) decides whether the block
  vanished or storage failed. It runs only while the breaker is closed;
  otherwise the read counts directly.

When either streak reaches `failure_threshold` the breaker opens for
`backoff_ms`: queries answer MISS without a check, queued checks and probes
are dropped, reads with a check result fail without I/O and spills are
dropped. Failures of work started before it opened do not extend it. Then it
is half-open: checks run again and one data transfer runs as the trial. A
successful trial closes the breaker and resets both streaks; a failed trial,
or a failed check started while half-open, opens it again. An answered check
does not close it.

Each transition (open, half-open, closed, open again) logs one WARNING on
the `kvcr` logger naming the new state; opening also gives the last error.
`get_stats` reports `g4_breaker_state` (0 closed, 1 open, 2 half-open) and
`g4_breaker_failures` (the larger streak).

## Telemetry

With `enable_telemetry` on, each G4 transfer handle (one per key) records one
transfer when it ends, the same way G3 does: a duration labelled `success` or
`failed`, and on success one block and its payload bytes.

| Scope | Transfer | Success |
| --- | --- | --- |
| `g4_fill` | Read into a G2 slot (`fetch`) | DONE before the op deadline |
| `g4_deliver` | Read into a framework destination (`deliver`) | DONE before the op deadline |
| `g4_spill` | Write of an evicted G2 block | Published (file renamed in place) |

A transfer still open when G4 turns off or closes is recorded as failed. A
spill that publishes after its deadline still records success.

`get_stats` also reports these cumulative counters. They count whether or not
telemetry is enabled:

| Counter | Counts |
| --- | --- |
| `g4_check_present`, `g4_check_absent` | Existence checks storage answered |
| `g4_check_error` | Checks that failed or passed their deadline; a late answer after a timeout does not count again |
| `g4_fill_ok`, `g4_fill_failed` | Ended fill transfers |
| `g4_deliver_ok`, `g4_deliver_failed` | Ended deliver transfers |
| `g4_spill_published` | Spills published, late ones included |

A check cancelled while still queued and a read-error probe count in none of
them.

## Environment

| Variable | Effect |
| --- | --- |
| `KVCR_NIXL_MODULE` | Python module providing NIXL (default `nixl`), for example `nixl_cu12` when the cu13 OBJ plugin cannot load. `nixl_cu12._api` is accepted too. The main agent and the G4 storage agent use the same module; a process must load only one NIXL build. A startup error naming it means the plugin did not load |

## File flavor operations

- Mount options: default NFS negative lookup caching can hide a block another
  host just published for 30 to 60 s; that costs a recompute, not wrong data.
  Use `lookupcache=positive` (or none) where possible.
- File mode is `0644`; every host that shares a namespace needs read access
  to the same UID/GID, and writers need write access to the directories.
- Crashed writers can leave `*.tmp.*` files; readers ignore them and storage
  cleanup removes them.
- Each host must be a writer: startup creates the namespace directories and
  writes, renames and removes a probe file.

## Close

`close()` drops G4 jobs that have not started, waits for started transfers to
end, joins every G4 worker, then releases what remains: open files, temp
files, G2 sources and pending results. A transfer that never ends makes
`close()` raise and leaves its resources in place.
