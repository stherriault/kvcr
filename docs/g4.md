# G4: unmanaged remote storage

> **Caller obligations**
>
> | Obligation | Why |
> | --- | --- |
> | Pass a `request_id` to `query` | A check result belongs to a request; no `request_id` means MISS |
> | Call `poll_completed` regularly | It is the only pump for G4 transfer completions, spill finish and deadlines. `query` drains check results too, but not transfers |
> | Call `discard_hint(request_id)` at request end | Drops the request's check subscriptions and results |
> | Hold a deliver destination named in an "uncertain" report until "quiesced" | NIXL may still write it. The default `on_resilience_event` handler only logs |
> | Treat `(FETCHING, G4)` as "existence check running", not "fill running" | G4 FETCHING differs from a G2 fill in progress |

G4 is storage someone else owns: an S3 object store through the NIXL `OBJ`
plugin (object flavor), or a shared file system such as NFS, Lustre or Weka
through the NIXL `POSIX` plugin (file flavor). KVCR writes blocks there when
it evicts them from its G2 DRAM pool and reads them back on demand. KVCR keeps
no G4 index: storage decides residency and eviction.

## Configuration

```python
from kvcr.config import G4Options, KVCRBackendConfigs

g4 = G4Options(
    flavor="file",
    key_prefix="tenant-a/model-x/base/bf16",
    key_layout=("",),
    root=Path("/mnt/shared/kvcr"),
)
KVCRBackendConfigs(local_dram=..., g4=g4)
```

| Field | Default | Meaning |
| --- | --- | --- |
| `flavor` | required | `"object"` or `"file"` |
| `key_prefix` | required | Namespace. Must name tenant, model, adapter and KV dtype unless the block keys already do |
| `key_layout` | required | Fixed piece schema of every block in the namespace (see below) |
| `root` | `None` | File flavor: the shared mount. Object flavor: must be `None` |
| `backend`, `backend_options` | `""`, `{}` | NIXL plugin (`OBJ` or `POSIX` by default) and its options. Credentials are redacted in `repr` |
| `max_inflight_checks` | 64 | Keys with a check started; more keys wait in a queue and still answer FETCHING |
| `max_check_results` | 65536 | Subscriptions, queued keys and unconsumed results; at the bound new lookups get MISS |
| `check_timeout_ms` | `operation_timeout_ms` | Core deadline of one existence check |
| `check_batch_max` | 32 | Object flavor: queued checks per `query_memory` call |
| `spill_timeout_ms` | `operation_timeout_ms` | Spill latch, independent of the deposit deadline |
| `miss_backoff_ms` | 1000 | Reserved; not applied yet |
| `direct_io` | `False` | File flavor: open block files with `O_DIRECT` |
| `failure_threshold`, `backoff_ms` | 5, 10000 | Circuit breaker |

Startup raises `ValueError` for: guard recovery together with G4, G4 without
local DRAM, a `key_layout` label that is not a configured pool, an object
flavor `key_layout` with more than one label, an object flavor with a `root`,
a file flavor without a usable `root`, and POSIX `use_uring` or
`use_posix_aio`.

## Naming and the key_layout schema

A block is stored as `{key_prefix}/{layout_tag}/{d[0:2]}/{d}`, where `d` is the
sha256 of the block key. `layout_tag` is 8 hex characters of sha256 over the
`key_layout` labels, the pool block sizes and the format version, so another
schema reads another name.

An object or file holds the pieces of `key_layout` back to back, with no
header, footer or checksum. `query` carries no layout, so every block in a
namespace uses this one schema.

- Spill: only keys whose G2 layout equals `key_layout` are written. Other keys
  are dropped at eviction (counted).
- Read: requested labels map to schema pieces by label. A partial or reordered
  read is served when the mapping is unambiguous; with repeated unnamed pools
  the requested order must equal the schema. Otherwise the key has no G4
  source (fetch) or fails (deliver).
- Object flavor: `key_layout` has exactly one label. A multi-piece OBJ write
  fails in NIXL and a multi-descriptor OBJ handle is unsafe on error.

**Sharing contract.** Hosts share blocks only if they use the same
`key_prefix`, `key_layout` labels, pool block sizes and format version.

## Threads and the caller pump

All storage-agent calls run on one G4 storage worker thread that owns a
dedicated NIXL agent. All file system calls of the file flavor (`stat`,
`open`, `fstat`, `ftruncate`, `fsync`, `rename`, `unlink`, `mkdir`, `close`)
run on one G4 file worker thread, in queue order. The main progress thread
never waits on storage.

There is no KVCR core thread. Completions are applied when the caller calls
`poll_completed`; `query` also applies finished existence checks and check
deadlines, so a driver that loops only on `query` still sees check results.

A core deadline frees the caller, not the worker: a hung HEAD or a hung shared
file system keeps the worker blocked and later G4 work waits behind it.

## Read path

1. `query(key, request_id)` for a key no other tier holds starts one existence
   check (or joins the one in flight) and returns `(FETCHING, G4)`.
2. The check ends as `(FETCHABLE, G4)` or MISS. A check that passes its
   timeout resolves MISS for every subscriber; until its late answer arrives
   the key keeps answering MISS.
3. `fetch` or `deliver` consumes the present result and reads the block with
   one transfer handle per key, straight into the G2 fill slot or the
   caller's DRAM destination. A deliver from G4 is not also placed in G2.

A failed, errored or timed-out transfer never reports SUCCESS: the G2 fill
slot never becomes ready, and a deliver destination is invalid after FAILED.
A deliver still not terminal at `abandon_timeout_ms` completes FAILED and
reports a `TransferError` with `state="uncertain"` naming the destination
regions; when the transfer ends a second report with `state="quiesced"`
follows. Between the two the caller must not reuse or free those regions.

**File size check.** The file flavor compares sizes for free: a `stat` size
other than the schema length is a MISS, an `fstat` mismatch at open fails the
read without counting against the breaker, and a short read fails. A file
replaced after open is served from the opened inode.

**Short read on objects.** The NIXL OBJ plugin completes a READ of a short
object with DONE and a partial fill, and its existence check ignores size.
KVCR cannot detect a short object; storage that truncates objects serves
wrong bytes as SUCCESS.

## Write path and the deposit stall

A LOCAL_G2 eviction with `MOVE_TO G4` writes the victim straight from its G2
slot, like G3. The pool allows one capacity spill in flight, so a deposit that
needs the slot waits (it stalls) for the whole G4 write. With a spill time `w`
and a deposit deadline `T`, at most floor(T / w) evicting deposits of one job
land; the rest fail at `T`.

The spill has its own `spill_timeout_ms`. A spill that finishes after it is
still published (counted as late, no breaker change). A spill that fails is
dropped, the G2 slot is retired and the policy's `decide_recovery` runs.

Atomic publish:

- File: create missing directories, open `name.tmp.{host}.{pid}.{rand64}` with
  `O_CREAT|O_EXCL`, write, `fsync`, close, `rename` to the final name. Readers
  never see a partial block. An `fsync`, close or `rename` error is a spill
  failure and the temp file is removed.
- Object: one whole-object PUT; the object is visible only when it completes.

Neither NIXL 1.5.0 S3 nor a hung shared file system has a request timeout: a
hung write keeps G2 admission blocked and `close()` raises.

## Environment

| Variable | Effect |
| --- | --- |
| `KVCR_NIXL_MODULE` | Python module providing NIXL (default `nixl`), for example `nixl_cu12` when the cu13 OBJ plugin cannot load. `nixl_cu12._api` is accepted too. The main agent and the G4 storage agent use the same module; a process must load only one NIXL build. A startup error naming it means the plugin did not load |
| `AWS_EC2_METADATA_DISABLED` | Set to `true` by KVCR only for the object flavor with static credentials and when unset, to skip the instance metadata probe at backend creation |

## File flavor operations

- Mount options: default NFS negative lookup caching can hide a block another
  host just published for 30 to 60 s; that costs a recompute, not wrong data.
  Use `lookupcache=positive` (or none) where possible.
- File mode is `0644`; every host that shares a namespace needs read access
  to the same UID/GID, and writers need write access to the directories.
- Crashed writers can leave `*.tmp.*` files; readers ignore them and storage
  cleanup removes them.
- Each host must be a writer: startup creates the namespace directories and
  writes, renames and removes a probe file.
