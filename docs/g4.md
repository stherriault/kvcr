# G4: unmanaged remote storage

> **Caller obligations**
>
> | Obligation | Why |
> | --- | --- |
> | Pass a `request_id` to `query` | A check result belongs to a request; no `request_id` means MISS |
> | Call `poll_completed` regularly | It is the only pump for G4 transfer completions, spill finish and deadlines. `query` drains check results too, but not transfers |
> | Call `discard_hint(request_id)` at request end | Drops the request's check subscriptions and results |
> | Hold a deliver destination named in an "uncertain" report until "quiesced" | NIXL may still write it. The default `on_resilience_event` handler only logs |
> | Treat `(FETCHING, G4)` as "existence check running", not "fill running" | G4 FETCHING differs from a G2 fill in progress |

G4 is storage someone else owns: an S3 object store through the NIXL `OBJ`
plugin (object flavor), or a shared file system such as NFS, Lustre or Weka
through the NIXL `POSIX` plugin (file flavor). KVCR writes blocks there when
it evicts them from its G2 DRAM pool and reads them back on demand. KVCR keeps
no G4 index: storage decides residency and eviction.

## Configuration

```python
from kvcr.config import G4Options, KVCRBackendConfigs

g4 = G4Options(
    flavor="file",
    key_prefix="tenant-a/model-x/base/bf16",
    key_layout=("",),
    root=Path("/mnt/shared/kvcr"),
)
KVCRBackendConfigs(local_dram=..., g4=g4)
```

| Field | Default | Meaning |
| --- | --- | --- |
| `flavor` | required | `"object"` or `"file"` |
| `key_prefix` | required | Namespace. Must name tenant, model, adapter and KV dtype unless the block keys already do |
| `key_layout` | required | Fixed piece schema of every block in the namespace (see below) |
| `root` | `None` | File flavor: the shared mount. Object flavor: must be `None` |
| `backend`, `backend_options` | `""`, `{}` | NIXL plugin (`OBJ` or `POSIX` by default) and its options. Credentials are redacted in `repr` |
| `max_inflight_checks` | 64 | Keys with a check started; more keys wait in a queue and still answer FETCHING |
| `max_check_results` | 65536 | Subscriptions, queued keys and unconsumed results; at the bound new lookups get MISS |
| `check_timeout_ms` | `operation_timeout_ms` | Deadline of one existence check, from submit while queued and from the worker's take once started |
| `check_batch_max` | 32 | Queued checks per `query_memory` call |
| `spill_timeout_ms` | `operation_timeout_ms` | Spill latch, independent of the deposit deadline |
| `direct_io` | `True` | File flavor: open block files with `O_DIRECT`; startup checks that the root accepts it |
| `failure_threshold`, `backoff_ms` | 5, 10000 | Circuit breaker |
| `close_timeout_ms` | 30000 | Total time `close()` waits for the G4 storage worker, a blocked storage call included, before it raises |

Startup raises `ValueError` for: guard recovery together with G4, G4 without
local DRAM, a `key_layout` label that is not a configured pool, an object
flavor `key_layout` with more than one label, an object flavor with a `root`,
a file flavor without a usable `root`, a file flavor `root` that refuses
`O_DIRECT` while `direct_io` is `True` (startup creates and opens a probe
file there with `O_DIRECT`), a file flavor with `direct_io` `True` and a
DRAM region that is not page aligned, and POSIX `use_uring` or
`use_posix_aio`.

The object flavor runs one existence check against the bucket at startup.
Absent or present both prove access; an error (wrong bucket, endpoint or
credentials) fails startup with a `RuntimeError` naming the bucket. This
check does not count toward the circuit breaker.

With the file flavor and `direct_io` `True`, every DRAM region G4 registers
(framework regions and local DRAM pools) must be page aligned: base address,
element `size` and, when set, `stride` must be multiples of the page size
(`os.sysconf("SC_PAGE_SIZE")`). Startup refuses otherwise and the error names
the region's address. Set `direct_io=False` to use unaligned regions. The
object flavor does not check alignment.

The default policy is `G4LRUPolicy` when G4 is configured without G3: every
LOCAL_G2 eviction becomes `MOVE_TO G4`. With G3 configured the default stays
`G3LRUPolicy` and G4 receives no spills; KVCR logs this at startup.

## Naming and the key_layout schema

A block is stored as `{key_prefix}/{layout_tag}/{d[0:2]}/{d}`, where `d` is the
sha256 of the block key. `layout_tag` is 8 hex characters of sha256 over the
`key_layout` labels, the pool block sizes and the format version, so another
schema reads another name.

An object or file holds the pieces of `key_layout` back to back, with no
header, footer or checksum. `query` carries no layout, so every block in a
namespace uses this one schema.

- Spill: only keys whose G2 layout equals `key_layout` are written. Other keys
  are dropped at eviction (counted).
- Read: requested labels map to schema pieces by label. A partial or reordered
  read is served when the mapping is unambiguous; with repeated unnamed pools
  the requested order must equal the schema. Otherwise the key has no G4
  source (fetch) or fails (deliver).
- Object flavor: `key_layout` has exactly one label. A multi-piece OBJ write
  fails in NIXL and a multi-descriptor OBJ handle is unsafe on error.

**Sharing contract.** Hosts share blocks only if they use the same
`key_prefix`, `key_layout` labels, pool block sizes and format version.

## Eviction model

KVCR never deletes a published block. Pick the eviction model of the
deployment and set it up on the storage side:

| Eviction model | Who removes blocks | Operator setup |
| --- | --- | --- |
| A. Treated as infinite, cleaned by age | An S3 lifecycle rule or an admin cleanup job | A lifecycle rule (or cleanup job) on `key_prefix`; also expire leftover `*.tmp.*` files |
| B. Storage is itself a cache | Storage, by its own LRU | Nothing |

A block that vanishes (model B) is a MISS at check time or a failed read
after it; it never opens the circuit breaker. Client-managed eviction (KVCR
deletes) is not supported.

## Threads and the caller pump

G4 adds one thread, the storage worker (`kvcr-g4-storage`), for both
flavors. It owns the one storage NIXL agent and makes every storage call:

| Work | Object flavor | File flavor |
| --- | --- | --- |
| Transfers | Register, post, poll and release on the OBJ backend | Register, post, poll and release on the POSIX backend |
| Existence checks | `query_memory` with `mem_type="OBJ"` (a HEAD per row) | `query_memory` with `mem_type="FILE"` (a `stat` per row) |
| Read-error probes | `query_memory`, one row | `os.stat` of the path, compared by `st_dev` and `st_ino` with the file the read opened |
| File system calls | None | `mkdir`, `open`, `ftruncate`, `fsync`, `rename`, `unlink` and `close` of spills; `open`, `fstat` and `close` of reads |

The worker does one thing at a time. A slow storage call (a hung HEAD, a
stuck `stat`, `open` or `fsync` on a shared file system) pauses all G4 work,
including the polling of transfers already posted, until it returns. Check
deadlines, the spill latch, read deadlines and the circuit breaker bound
what callers wait for; the worker itself stays blocked. The main progress
thread never waits on storage.

There is no KVCR core thread. Completions are applied when the caller calls
`poll_completed`; `query` also applies finished existence checks and check
deadlines, so a driver that loops only on `query` still sees check results.

If the storage worker dies, G4 takes no new work until restart: lookups
answer MISS, reads find no G4 source and spills are dropped. One WARNING
says so, and `poll_completed` keeps returning results for the other tiers.
Every open G4 operation completes FAILED. Memory a posted transfer handle
may still touch stays pinned until close and is never reused: the G2 fill
slot, the spill source (a deposit waiting for that slot fails at its
deadline) and the deliver destination, which is reported "uncertain".
`close()` may then report the tier not quiescent. Memory of transfers never
posted is freed as for any failed operation.

An unexpected error in one file system call ends that transfer as failed
and the worker goes on.

## Read path

1. `query(key, request_id)` for a key no other tier holds starts one existence
   check (or joins the one in flight) and returns `(FETCHING, G4)`.
2. The check ends as `(FETCHABLE, G4)` or MISS. While the check waits in
   the worker's queue its deadline is submit time plus `check_timeout_ms`;
   if that passes it is cancelled, answers MISS and does not count toward
   the breaker. When the worker takes it the deadline restarts from the
   take; a started check past it answers MISS for every subscriber, counts
   once and, until its late answer arrives, the key keeps answering MISS.
   Queued checks share `query_memory` calls of up to `check_batch_max`
   rows. One OBJ call runs its HEADs concurrently, so check time is per
   call, not per key.
3. `fetch` or `deliver` consumes the present result and reads the block with
   one transfer handle per key, straight into the G2 fill slot or the
   caller's DRAM destination. A deliver from G4 is not also placed in G2.

A failed, errored or timed-out transfer never reports SUCCESS: the G2 fill
slot never becomes ready, and a deliver destination is invalid after FAILED.
A deliver still not terminal at `abandon_timeout_ms` completes FAILED and
reports a `TransferError` with `state="uncertain"` naming the destination
regions; when the transfer ends a second report with `state="quiesced"`
follows. Between the two the caller must not reuse or free those regions.

**File check.** The file flavor checks a block with the NIXL POSIX file
query: `query_memory` with `mem_type="FILE"` and the row `(0, 0, 0, path)`
for the final path. The answer is `None` for a missing file, or the file's
`stat` fields as decimal strings (`size`, `mode`, `mtime`). The block is
FETCHABLE only when `size` equals the schema length and `mode` is a regular
file; a directory, a FIFO or another size is a MISS. A query that raises,
or an answer without a numeric `size` and `mode`, is a check error and counts
toward the breaker, so a change in the answer format cannot turn every block
into a silent MISS. An `fstat` size mismatch at open fails the
read without counting against the breaker, and a short read fails.

**File replaced or removed during a read.** What a read in flight sees
depends on the file system:

- Local file systems and Lustre (by POSIX rules; not yet tested on Lustre)
  keep the opened file readable, so the read
  finishes from the copy it opened.
- NFS does not keep a file that another host replaced or removed: the read
  fails. The re-check then stats the path and compares `st_dev` and `st_ino`
  with the opened file. A different file or no file means the block changed
  under the read: the read fails without counting against the breaker, and
  the next lookup finds the new copy or a MISS.

**Short read on objects.** The NIXL OBJ plugin completes a READ of a short
object with DONE and a partial fill, and its existence check ignores size.
KVCR cannot detect a short object; storage that truncates objects serves
wrong bytes as SUCCESS.

## Write path and the deposit stall

A LOCAL_G2 eviction with `MOVE_TO G4` writes the victim straight from its G2
slot, like G3. The pool allows one capacity spill in flight, so a deposit that
needs the slot waits (it stalls) for the whole G4 write. With a spill time `w`
and a deposit deadline `T`, at most floor(T / w) evicting deposits of one job
land; the rest fail at `T`.

The spill has its own `spill_timeout_ms`. A spill past it counts one data
failure, releases the half-open trial if it held it and stops blocking G2
admission, so the next deposit can evict another victim; its G2 source stays
claimed until the write ends. A spill that finishes after it is still
published (counted as late, with no second count). A spill that fails is
dropped, the G2 slot is retired and the policy's `decide_recovery` runs.

Atomic publish:

- File: create the block's directory the first time this process writes
  into it (again after an open error there, such as storage cleanup
  removing it), open `name.tmp.{host}.{pid}.{rand64}` with `O_CREAT|O_EXCL`,
  write, `fsync`, close, `rename` to the final name. Readers
  never see a partial block. An `fsync`, close or `rename` error is a spill
  failure and the temp file is removed.
- Object: one whole-object PUT; the object is visible only when it completes.

**Two writers of one key.** Nodes do not check whether a block exists before
spilling it, so two nodes can spill the same key at the same time. Both
writes succeed and the last one to publish wins:

| Flavor | What happens | What readers see |
| --- | --- | --- |
| File | Each node writes its own temp file (the name is unique per host, process and random suffix), then renames it to the final name. The second `rename` replaces the first file | One whole copy or the other, never a mix. A read in flight on NFS fails as above |
| Object | Each node PUTs the whole object. The store keeps the last PUT | One whole object from one writer. A GET already running keeps the version it started on |

Either copy is valid for the key, since the key names the model and layout.
The cost is a second write of the same block; no error is raised and the
breaker does not count it.

Neither NIXL 1.5.0 S3 nor a hung shared file system has a request timeout: a
hung write holds its G2 slot until it ends, and `close()` raises.

## Failure handling and the circuit breaker

The breaker keeps two streaks of consecutive failures, counting at most one
failure per logical operation (one fetch, one deliver, one spill, one check,
or one OBJ check batch):

| Streak | Counts | Reset by |
| --- | --- | --- |
| Check | A check error, a started check past its deadline, a read-error probe that errors | Any answered check, a probe that finds the block gone |
| Data | A READ or WRITE error, a read past its deadline, a spill past its deadline, a spill or publish error, a probe that finds the block still there | A successful read or an in-time spill |

- Never counts: a check that answers absent or present, a check cancelled
  while still queued, a missing file or a size mismatch at open, a late
  answer to a check already counted at its deadline, a late spill DONE.
- After a read error a probe (HEAD or re-stat) decides whether the block
  vanished or storage failed. It runs only while the breaker is closed;
  otherwise the read counts directly.

When either streak reaches `failure_threshold` the breaker opens for
`backoff_ms`: queries answer MISS without a check, queued checks and probes
are dropped, reads with a check result fail without I/O and spills are
dropped. Failures of work started before it opened do not extend it. Then it
is half-open: checks run again and one data transfer runs as the trial. A
successful trial closes the breaker and resets both streaks; a failed trial,
or a failed check started while half-open, opens it again. An answered check
does not close it.

Each transition (open, half-open, closed, open again) logs one WARNING on
the `kvcr` logger naming the new state; opening also gives the last error.
`get_stats` reports `g4_breaker_state` (0 closed, 1 open, 2 half-open) and
`g4_breaker_failures` (the larger streak).

## Telemetry

With `enable_telemetry` on, each G4 transfer handle (one per key) records one
transfer when it ends, the same way G3 does: a duration labelled `success` or
`failed`, and on success one block and its payload bytes.

| Scope | Transfer | Success |
| --- | --- | --- |
| `g4_fill` | Read into a G2 slot (`fetch`) | DONE before the op deadline |
| `g4_deliver` | Read into a framework destination (`deliver`) | DONE before the op deadline |
| `g4_spill` | Write of an evicted G2 block | Published (file renamed in place, or the PUT completed) |

A transfer still open when G4 turns off or closes is recorded as failed. A
spill that publishes after its deadline still records success.

`get_stats` also reports these cumulative counters. They count whether or not
telemetry is enabled:

| Counter | Counts |
| --- | --- |
| `g4_check_present`, `g4_check_absent` | Existence checks storage answered |
| `g4_check_error` | Checks that failed or passed their deadline; a late answer after a timeout does not count again |
| `g4_fill_ok`, `g4_fill_failed` | Ended fill transfers |
| `g4_deliver_ok`, `g4_deliver_failed` | Ended deliver transfers |
| `g4_spill_published` | Spills published, late ones included |

A check cancelled while still queued and a read-error probe count in none of
them.

## Lifetime rule and POSIX modes

Destinations, G2 sources, registrations and file descriptors are released only
after the storage worker released the transfer handle at DONE or ERR. That
proves the transfer stopped only because:

- object flavor: each OBJ handle carries one descriptor;
- file flavor: POSIX uses linux AIO. KVCR sets `use_aio=true` and rejects
  `use_uring` and `use_posix_aio`, whose terminal state can be reported while
  I/O still runs.

**Buffered vs O_DIRECT.** With `direct_io=False` a buffered POSIX READ runs
inside `io_submit` on the storage worker, so file reads serialize there and
write cost lands in `fsync`. `O_DIRECT` (the default) needs page-aligned
DRAM regions (address, size and stride), which startup checks.

## Environment

| Variable | Effect |
| --- | --- |
| `KVCR_NIXL_MODULE` | Python module providing NIXL (default `nixl`), for example `nixl_cu12` when the cu13 OBJ plugin cannot load. `nixl_cu12._api` is accepted too. The main agent and the G4 storage agents use the same module; a process must load only one NIXL build. A startup error naming it means the plugin did not load |
| `AWS_EC2_METADATA_DISABLED` | Operator setting; KVCR never changes the process environment. Set it to `true` for an S3-compatible endpoint that is not AWS, or whenever credentials are static: otherwise the AWS SDK probes the instance metadata service at backend creation and startup is slow (about 6 s in our measurement). Leave it unset when credentials come from the instance role |

## File flavor operations

- Mount options: default NFS negative lookup caching can hide a block another
  host just published for 30 to 60 s; that costs a recompute, not wrong data.
  Use `lookupcache=positive` (or none) where possible.
- File mode is `0644`; every host that shares a namespace needs read access
  to the same UID/GID, and writers need write access to the directories.
- Crashed writers can leave `*.tmp.*` files; readers ignore them and storage
  cleanup removes them.
- Each host must be a writer: startup creates the namespace directories and
  writes, renames and removes a probe file.

## Close

`close()` drops G4 jobs that have not started (queued checks, probes and
transfers), waits for started transfers to end, joins the storage worker,
then releases what remains: open files, temp files, G2 sources and pending
results. A transfer that never ends makes `close()` raise and leaves its
resources in place.

The storage worker sees the close request only between calls. A call
blocked in storage (a hung or refused S3 endpoint can keep `query_memory`
busy for tens of seconds, a refused connection measured about 25 s; a hung
mount can do the same to a file call) is waited out for at most
`close_timeout_ms` in total, the last short join included. If the worker is still running then, `close()`
raises "G4 storage worker did not stop" and KVCR joins it again at
interpreter exit, so the process does not abort with native threads still
running.

During an outage each new key's check times out at `check_timeout_ms` and
counts once; checks still queued behind the hung call are cancelled at their
deadline without counting, and a key whose own check is still stuck answers
MISS without a new check, so repeated lookups of one key do not open the
breaker. Recovery waits until the storage worker leaves the hung call, then for
the half-open trial.
